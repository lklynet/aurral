---
title: Track matching architecture
description: How Aurral selects recordings and verifies downloaded releases.
---

Aurral matches tracks with native JavaScript rules. The matcher has no Python runtime, external service, or audio fingerprint dependency. Provider adapters supply only evidence the provider actually exposes; they do not turn a missing artist, duration, or recording ID into a match.

## Decision path

`trackIdentity.js` builds the requested recording. `candidateNormalizer.js` and the source adapters map search results into comparable candidates. `nativeMatcher.js` applies one versioned policy to recording contradictions, ranking, release fit, and one-to-one file assignment. `decisionEngine.js` adds provider evidence and returns `accept`, `verify`, `review`, or `reject` for each search result.

The same native matcher checks original file tags after download in `postDownloadValidator.js`. Aurral writes its own tags only after verification. A known conflicting recording ID, variant, artist, or duration cannot be overridden by a strong title score. Missing evidence does not count as agreement. A duration-only conflict with otherwise matching original tags is held for review; a file without usable original identity tags is not imported automatically.

Filename titles retain dash-separated version suffixes. A remaster can match the original recording, while a radio edit must match the requested version. Matching folds Latin accents and treats canonically equivalent Unicode spellings alike. If either core title contains non-Latin letters, different normalized core titles are contradictions, even when artist, duration, or recording ID agrees. This rule also applies to downloaded filename evidence and album file assignment. Transliteration and fuzzy spelling differences in those titles require an explicit user choice.

`MATCH_POLICY.version` is recorded with matcher decisions and exposed through the health response. Change the policy in one place, then run the fixture harness and the cross-source regression tests.

## Album release grabs

Aurral-managed album requests keep one job per missing track. When Soulseek, Usenet, or deemix is enabled, the first pending job reserves its siblings for one release attempt. Usenet submits one NZB, Soulseek submits one folder batch, and deemix submits one album URL. The completed files are assigned to sibling jobs without reusing a file. Each assigned file must pass its own post-download check before it moves into the Aurral library. Missing, unreadable, contradictory, or failed files leave their jobs pending for per-track fallback. If the attempt ends early, for example because the first job fails or is removed, the reserved jobs also return to per-track search.

The release attempt follows configured source priority. yt-dlp remains a per-track source. Lidarr-managed albums continue through Lidarr. Cancellation removes only work owned by the album request, and queued pipeline state resumes after a worker restart.

## Adding a source

1. Declare the evidence the source provides in `candidateNormalizer.js`.
2. Map provider results through `buildSourceCandidates()` and keep provider-specific availability checks at the adapter boundary.
3. Use the shared post-download validator before writing metadata or importing files.
4. For whole-release acquisition, feed the completed file paths to `finishAlbumGrab()` and test partial and failed downloads.

## Verification

`.tests/track-matching/fixtures/` contains identity-disjoint development and acceptance cases derived from CC0 MusicBrainz data. Run `node .tests/track-matching/native-evaluation.mjs` for per-flow correct, wrong, abstention, contradiction, and yield counts. The held-out acceptance run is a release gate; tune rules against the development split. Cross-source and download tests cover provider mapping, actual audio tags, one-grab imports, partial failures, cancellation, and fallback.

Metadata cannot distinguish two recordings whose visible evidence is identical. Aurral does not use audio fingerprints. If that case matters for an installation, a user can review the downloaded file before import.
