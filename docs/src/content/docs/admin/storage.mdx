---
title: Storage and backups
description: Where Aurral keeps its data and media, and what to back up.
---

Aurral keeps its own data separate from your music. It also needs the same view of the media files as your download clients, your playback server, and Lidarr if you use it.

For the full mount setup, follow [Filesystem and mounts](/getting-started/storage/). In short, mount your media root, and set the Downloads Folder to a path inside Aurral, such as `/data/downloads/aurral`. If you use Lidarr, mount the Lidarr media root at the same path that Lidarr uses.

## Storage locations

| Path             | Contents                                                                                                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/config`        | The database, settings, users, sessions, caches, playlist jobs, and the default yt-dlp staging folder. Mount it with `./config:/config`. Do not share it with other applications. |
| `/data`          | The shared media root. Mount the same host folder here in Aurral, Lidarr, your download clients, and your playback servers.                                                       |
| Downloads Folder | Aurral's permanent tracks, temporary flow tracks, and playlist artwork. Set it in **Settings > Library > Downloads folder > Path**, for example `/data/downloads/aurral`.         |

yt-dlp writes downloads to `/config/_staging` first. To use another disk, mount it and select it in **Settings > Downloads > yt-dlp > Staging path**. Keep this folder outside every media server library, so that servers do not scan unfinished files.

## Back up your data

Admins can download a backup in **Settings > General > Backup**. It holds settings, users, playlists, flows, listening history, and custom artwork. It also holds your integration passwords and API keys, so keep it private.

To restore, choose the backup file in the same place. Aurral replaces all of its data with the backup and restarts, and everyone signs in again. The data it replaced stays in `/config/before-restore-<date>`. Aurral comes back on its own when the container has a restart policy such as `restart: unless-stopped`. Otherwise, start it again to finish the restore.

A restore keeps the folder paths from the backup. On a new host, mount your media at the same paths, or update them in Settings.

A backup does not include music. Also back up:

- The Downloads Folder. Without Lidarr, it holds all of your music.
- The Compose file and the environment file with your host paths.

You can also copy the whole `/config` folder while Aurral is stopped.

## Library safety

- Lidarr is optional. Aurral and Lidarr each keep their own folders. While Lidarr is connected, the Library shows both without moving files. Turning Lidarr off removes its music from the Library and leaves the files on disk.
- Aurral never writes to or deletes files in a Lidarr root folder. Changes to Lidarr artists and albums go through Lidarr.
- Aurral does not move artists, albums, or files between Aurral and Lidarr.
- Aurral keeps its own media in the Downloads Folder. Flow files use `_flows`. Permanent tracks use `Artist/Album/Track` folders.
- The Downloads Folder and a Lidarr root folder can overlap, but it is not recommended. See [Settings warn that roots overlap](/admin/troubleshooting/#settings-warn-that-roots-overlap).
