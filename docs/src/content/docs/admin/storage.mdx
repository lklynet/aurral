---
title: Storage and backups
description: Where Aurral keeps its data and media, and what to back up.
---

Aurral keeps its own data separate from your music. It also needs the same view of the media files as your download clients and your playback server.

For the full mount setup, follow [Filesystem and mounts](/getting-started/storage/). In short, mount your media root, and set the Library folder to a path inside Aurral, such as `/data/downloads/aurral`. Mount any [read-only folders](/using/library/#add-music-aurral-only-reads) too.

## Storage locations

| Path           | Contents                                                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/config`      | The database, settings, users, sessions, caches, playlist jobs, and the default yt-dlp staging folder. Mount it with `./config:/config`. Do not share it with other applications. |
| `/data`        | The shared media root. Mount the same host folder here in Aurral, your download clients, and your playback servers.                                                               |
| Library folder | Aurral's permanent tracks, temporary flow tracks, and playlist artwork. Set it in **Settings > Library > Library folder > Path**, for example `/data/downloads/aurral`.           |

yt-dlp writes downloads to `/config/_staging` first. To use another disk, mount it and select it in **Settings > Downloads > yt-dlp > Staging path**. Keep this folder outside every media server library, so that servers do not scan unfinished files.

## Back up your data

Admins can download a backup in **Settings > General > Backup**. It holds settings, users, playlists, flows, listening history, and custom artwork. It also holds your integration passwords and API keys, so keep it private.

To restore, choose the backup file in the same place. Aurral replaces all of its data with the backup and restarts, and everyone signs in again. The data it replaced stays in `/config/before-restore-<date>`. Aurral comes back on its own when the container has a restart policy such as `restart: unless-stopped`. Otherwise, start it again to finish the restore.

A restore keeps the folder paths from the backup. On a new host, mount your media at the same paths, or update them in Settings.

A backup does not include music. Also back up:

- The Library folder and your read-only folders. They hold all of your music.
- The Compose file and the environment file with your host paths.

You can also copy the whole `/config` folder while Aurral is stopped.

## Library safety

- Aurral never writes to or deletes files in a read-only folder. Removing a read-only folder takes its music out of the Library and leaves the files on disk.
- Aurral keeps its own media in the Library folder. Flow files use `_flows`. Permanent tracks use `Artist/Album/Track` folders.
