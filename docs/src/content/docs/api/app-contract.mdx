## Version and capabilities

`GET /api/health/bootstrap` returns the JSON API contract without authentication:

```json
{
  "api": {
    "version": 2,
    "features": ["libraryStatusFilter"]
  }
}
```

`api.version` is a positive integer. It changes when a breaking change removes a
contract field, changes its type or meaning, or changes a required request
parameter. New optional fields and capabilities do not change the version.
Clients ignore unknown fields and feature names.

`appVersion` identifies the Aurral build. Nightly and preview build identifiers
are not API versions. The Subsonic protocol version is separate.

Feature names describe server capabilities added after version 2. They do not
grant a permission or guarantee that an optional service is configured or
available. The feature list is the same before and after sign-in.

Every version 2 server has the capabilities below, so `features` does not list
them. Version 1 servers listed each one under its feature name.

Each capability added after version 2 gets its own name, and Aurral adds the
name only when its routes are available. Clients check for that name before
using those routes. An absent name means the server does not promise it.

| Feature               | Capability                                                                                                                                                                                                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `libraryStatusFilter` | Artist and album pages from `GET /api/library` accept `status=monitored`, `unmonitored`, or `missing`. An album is missing tracks when some are unavailable, unless Aurral manages it and it is not released yet. An artist is missing tracks when one of its albums is. Other values return `400`. |

The registry is `backend/config/apiContract.ts`. A capability change updates that
registry and this reference. The response checks in `.tests/api/` pin the fields
below through HTTP requests.

## Authentication and errors

Password sign-in uses `POST /api/auth/login` with a JSON body containing
`username` and `password`. Subsequent requests use
`Authorization: Bearer SESSION_TOKEN`. The [API overview](/api/overview/) covers
API keys and other authentication methods.

A JSON error contains a string `error`. Other error fields are optional.
`401` means authentication failed or is missing. `403` means the credential
lacks the required permission. `404` means the requested resource is missing.
Service failures can return other error statuses. Clients inspect the status
before interpreting a success response.

## Stable response fields

The routes and fields below form version 2 of the app contract. Responses may
contain additional fields. Arrays can be empty. Fields marked nullable can be
`null`.

`user` contains numeric `id`, strings `username` and `role`, and object
`permissions`. An authenticated bootstrap also includes `user`.

Discovery artist entries contain nullable string `id` and `image`, strings
`name` and `type`, and array `tags`. Search artist entries contain string `id`,
`name`, and `type`, nullable string `image`, array `tags`, and boolean
`inLibrary`. Search album entries contain strings `id`, `title`, `artistName`,
`type`, and `status`, and boolean `inLibrary`.

Trending charts are the same for every user, except `libraryPlaylistId`.
`region` is the region code the charts follow, `001` for worldwide.
`regionChoice` is `auto` when the charts follow the server's location, or the
region code an admin picked. Each chart section is `null` until
Aurral has loaded it, and a section keeps its last loaded chart when a refresh
fails. `songs` contains strings `playlistId` and `playlistName`, nullable string
`libraryPlaylistId`, array `items`, and nullable object `spotlight`.
`playlistId` is the Deezer playlist ID, and `libraryPlaylistId` is set when the
user saved the chart as a playlist. `spotlight` contains numeric `daysAtTop` and
array `ranks`: the No. 1 song's rank on each of the last 14 days, oldest first,
with `null` for days it was off the chart. It is `null` until Aurral has saved
two days of the chart.

Chart song entries contain strings `key`, `trackName`, and `artistName`, numeric
`position`, nullable strings `albumName`, `artworkUrl`, and `preview_url`, and
nullable numeric `durationMs`. Entries in `songs.items` also contain `movement`:
the number of places the song moved since the previous saved day, `"new"`, or
`null` before Aurral has saved two days. Album entries contain strings `key`,
`name`, and `artistName`, numeric `position`, and nullable strings `artworkUrl`,
`releaseDate`, and `genre`. Artist entries contain strings `key` and `name`,
numeric `position`, nullable strings `imageUrl` and `mbid`, and nullable numeric
`fans`. `genreShare` contains numeric `total` and `other` and array `genres` of
objects with string `name` and numeric `count`. `genres` entries contain numeric
`id`, string `name`, and arrays `covers` and `artists`. A genre chart that Aurral
has not loaded returns `404`.

A resolved link's `artist` contains string `name` and nullable string `mbid`.
`album` contains string `title` and nullable string `mbid`; it is `null` for
artist links and for tracks whose album the service does not report. `track`
contains string `title` and nullable string `mbid`; it is `null` unless `kind`
is `track`. A `null` MusicBrainz ID means Aurral found no match, so search by
name instead. An unsupported link returns `400`.

Artist release-group entries contain strings `id`, `title`, and `primary-type`,
array `secondary-types`, and nullable string `first-release-date`.

Library artist, album, and track entries use numeric `id` and string
`identityKey`. Artists have string `name`, albums have string `title`, and
tracks have strings `title` and `artistName`, nullable string `mbid`, and array
`files`. These IDs are different from MusicBrainz IDs and Subsonic IDs.

Album lookup objects contain boolean `inLibrary` and `monitored`, nullable
strings `libraryAlbumId` and `libraryArtistId`, string `status`, numeric
`trackCount` and `trackFileCount`, and array `ownedTrackMbids`. An absent key
means that the server did not find the album. `ownedTrackMbids` identifies
available tracks; it does not promise a complete album track list.
`libraryAlbumId` and `libraryArtistId` are null when the album is not in the
Library.

Flow objects contain strings `id` and `name`, numeric `size` and `ownerUserId`,
boolean `enabled`, and object `mix`. Existing legacy flows can have a nullable
`ownerUserId`. Download job objects contain strings `id`, `status`,
`artistName`, `trackName`, and `playlistType`, and nullable string `streamFormat`.

Activity objects contain string `id`, `status`, and `title`, and nullable
strings `kind`, `artistName`, and `trackName`. Activity combines several kinds
of events, so clients do not assume that every item describes a track.

Approval imports the held file and marks the job done. Denial removes the held
file and returns the job to the download queue. A missing or no-longer-blocked
job returns `404` with `error`.

## Changes from version 1

Version 2 removed these version 1 names. Apps that still read them need the
current names.

| Version 1                                                                   | Version 2                                               |
| --------------------------------------------------------------------------- | ------------------------------------------------------- |
| `GET /api/library/canonical`                                                | `GET /api/library`                                      |
| `/api/library/canonical-stream/:albumId/:trackId`                           | `/api/library/stream/:albumId/:trackId`                 |
| `PUT /api/library/canonical/artists/:id/mbid`                               | `PUT /api/library/artists/:id/mbid`                     |
| `readPath=canonical`                                                        | `readPath=library`                                      |
| `/api/playlists/shared-playlists`                                           | `/api/playlists/static-playlists`                       |
| `sharedPlaylists`, `sharedPlaylistStats`, `sharedStats`                     | `staticPlaylists`, `staticPlaylistStats`, `staticStats` |
| `accessFlow` permission                                                     | `accessPlaylists`                                       |
| `canonical`, `canonicalInLibrary`                                           | `fromLibraryIndex`                                      |
| `canonicalId` on Library artists, albums, and tracks                        | `id`                                                    |
| `canonicalId` on search results, artist lookups, and Aurral album responses | `libraryId`                                             |
| `albumCanonicalId` on track search results, `canonicalAlbumId` on activity  | `libraryAlbumId`                                        |
| `canonicalAlbumId`, `canonicalArtistId` on album lookups                    | `libraryAlbumId`, `libraryArtistId`                     |
| `canonicalTrackId` in `POST /api/library/downloads/track`                   | `libraryTrackId`                                        |
| `managedBy` on Library artists, albums, tracks, and album lookups           | Boolean `managed`                                       |
| `managedBy` and `triggerSearch` in `POST /api/library/albums/request`       | Removed                                                 |
| `/api/library/albums/aurral/:albumId`                                       | `/api/library/albums/:albumId`                          |
| `/api/library/tracks/aurral/:trackId`                                       | `/api/library/tracks/:trackId`                          |
| `aurral:<albumId>` in `GET /api/library/downloads/status`                   | The Library album ID                                    |
| `monitorOption` on artist requests and on artists and albums                | `monitoring` on requests. Removed from responses        |

In version 1, `libraryAlbumId` and `libraryArtistId` on album lookups and
album search results held the IDs of the service that manages the album. In
version 2 they hold Library IDs on lookups. Version 2 has no `providerAlbumId`
or `providerArtistId`.
