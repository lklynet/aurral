Aurral runs in Docker. It needs two mounts:

- `/config` for Aurral's database, settings, users, and jobs.
- A media mount for the Downloads Folder, completed downloads, and the Lidarr library if you use Lidarr.

Read [Filesystem and mounts](/getting-started/storage/) before you write the Compose file. Every service that shares files with Aurral must see those files at the same path.

## Minimal Compose file

```yaml
services:
  aurral:
    image: ghcr.io/lklynet/aurral:latest
    restart: unless-stopped
    ports:
      - "3001:3001"
    environment:
      - PUID=${PUID:-1000}
      - PGID=${PGID:-1000}
    volumes:
      - ${MEDIA_ROOT:-/srv/media}:/data
      - ./config:/config
```

Replace `/srv/media` with your host media folder. If you use Lidarr, use the host folder that Lidarr already mounts. Keep `/data` as the container side of the mount, so that every media service sees the same paths.

For example, the host folder `/srv/media/downloads/aurral` is `/data/downloads/aurral` inside Aurral. In Aurral settings, always enter the container path.

Do not share `/config` with another service.

## Start Aurral

```bash
docker compose up -d
```

1. Open `http://localhost:3001`.
2. Create the admin account.
3. Connect Lidarr, or select **Skip for now** and set the Downloads Folder.
4. Run the storage checks.

Continue with [First run](/getting-started/first-run/).

## Choose an image tag

| Tag | Contents | Use it when |
| --- | --- | --- |
| `latest` | The newest stable release | You want a tested release. |
| `2.10.0`, `2.10`, `2` | An exact version, or the newest release in that line | You pin versions or need to roll back. |
| `nightly` | Every change merged since the last release | You want fixes and features early and can report bugs. |
| `pr-<number>` | The preview image for an open pull request | A maintainer asked you to test a proposed change. |

Aurral checks for a newer build in your channel. When one exists, an update icon appears in the top-right corner. Select it to read the changes and open the GitHub release or commit list.

On a nightly or preview image, the sidebar shows artwork for that channel. To hide it, turn off **Profile > Appearance > Environment art**.

:::caution
`nightly` is not a stable release. Back up `./config` before you switch to it.

Nightly and preview images support `linux/amd64` only. On ARM, use `latest` or a version tag.
:::

The [Release Readiness issues](https://github.com/lklynet/aurral/issues?q=is%3Aissue+label%3Arelease-readiness+sort%3Aupdated-desc) track the current nightly. The pinned issue lists the nightly candidate and the changes it includes.

## Test a pull request preview

The pull request conversation on GitHub gives the `pr-<number>` tag and the test steps.

1. Back up `./config`.
2. Change the Aurral image to the preview tag.
3. Run `docker compose pull aurral && docker compose up -d aurral`.
4. Test the behavior that the pull request changes.
5. Change the image back to the tag that you used before.
